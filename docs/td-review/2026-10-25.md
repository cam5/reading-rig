#### TD-001 · bug · #235 · Rollback plan says "Nothing deploys to Railway" for build/boot changes

Status: **closed**: fixed in stacked PR #237 (`81675e8`, based on #235’s branch)

- **Where:** `scripts/lib/rollbackPlan.ts:143-150` (`packageJsonChanges`), plus the `PIPELINE_FILES`/app file lists and the `railway: false` default for "other".
- **Observed:** if a PR changes only `postinstall`, `prebuild` or `build` in package.json, it's classified "no-runtime". Railway's `npm ci` runs `postinstall` and its build runs `prebuild`/`build`. The same happens for a PR touching only `scripts/lib/db.ts` (which `scripts/setup-agent.ts:4` imports, and which runs from release.ts on every boot), `prisma.config.ts`, `vite.config.ts`, `react-router.config.ts`, or `scripts/subsetCaprasimo.ts`/`instanceFraunces.ts`. The plan prints LOW and "Nothing in this change set deploys to Railway."
- **Root cause:** only `scripts.start` and `scripts.release` are compared, and files it doesn't recognise default to `railway: false`.
- **Fix:** also compare `postinstall`, `prebuild`, `build`, `prestart` and `prerelease`. Add `scripts/lib/db.ts`, `prisma.config.ts` and the font scripts to the pipeline list, and the vite/react-router configs to the app list. Have "other" default to `railway: true`.
- **Verify:** unit cases in `scripts/lib/rollbackPlan.test.ts` for a package.json change that touches only `postinstall`, and for a change that touches only `scripts/lib/db.ts`.

#### TD-002 · bug · #235 · An explicit base uses a two-dot diff, which reverses main's changes

Status: **closed**: fixed in stacked PR #237 (`81675e8`, based on #235’s branch)

- **Where:** `scripts/rollbackPlan.ts:39-47`.
- **Observed:** `npm run rollback:plan -- origin/main` on a branch that is behind main runs `git diff origin/main HEAD`. A migration added on main since the branch point then shows as `D` (deleted), and the plan reports "HIGH … was deleted". RUNBOOK advertises the `[<base>]` argument, so people will hit this.
- **Root cause:** only the no-argument default goes through `merge-base`.
- **Fix:** always resolve `git merge-base <base> <head>`, or diff `${base}...${head}`. Also put `--end-of-options` before the revisions.
- **Verify:** run on a branch behind main with an explicit base; main's migrations must not appear.

#### TD-003 · bug · #235 · An added migration that can't be read is reported as non-destructive

Status: **closed**: fixed in stacked PR #237 (`81675e8`, based on #235’s branch)

- **Where:** `scripts/lib/rollbackPlan.ts:190-193`, together with `showAt` in `scripts/rollbackPlan.ts:29-35`, which swallows errors.
- **Observed:** if `git show` fails, `contents` is `undefined` and `destructive` is `[]`. The migration is reported MEDIUM with no snapshot step, even if it drops a table.

- **Verify:** a unit case with `contents: undefined`.

#### TD-004 · bug · #235 · The destructive-SQL heuristic misses some statements

Status: **closed**: fixed in stacked PR #237 (`81675e8`, based on #235’s branch)

- **Where:** `scripts/lib/rollbackPlan.ts:90-96`.
- **Observed:**
  - `UPDATE OR REPLACE "X" SET …` and `UPDATE OR IGNORE` don't match `\bUPDATE\s+\S+\s+SET\b`.
  - `REPLACE INTO` and `INSERT OR REPLACE` aren't checked at all.
  - Comment stripping doesn't respect string literals: `'a--b'` hides the rest of the line, and a `/*` inside a `--` comment strips up to the next `*/`.
  - Nothing in `prisma/migrations` hits these today; it matters for hand-written SQL.
- **Fix:** match `\bUPDATE\b[^;]*?\bSET\b`, add `\b(REPLACE\s+INTO|INSERT\s+OR\s+REPLACE)\b`, and strip `--` comments before `/* */` comments.
- **Verify:** unit cases for each statement form.

#### TD-005 · bug · #232 · Paging `actions/runs` can count a run twice

Status: **closed**: fixed in stacked PR #238 (`d12d528`, based on #232’s branch)

- **Where:** `scripts/ciSignalNoise.ts:151-159`.
- **Observed:** pages are fetched by page number from a newest-first list. If a run starts mid-fetch, the last run on page 1 comes back as the first run on page 2. It's then counted twice in the score and minutes, and its attempts are fetched twice. This is likely at the default `--limit 200`, which takes two pages.
- **Fix:** keep a `Set` of seen run `id`s and skip repeats before `raw.splice(limit)`.
- **Verify:** extract the page merge into a pure helper and unit-test it with pages that overlap.

#### TD-008 · bug · #232 · File lists cut off at 300 files can misclassify a run as irrelevant

#### TD-012 · bug · #233 · `--runs=30` is silently ignored, and a URL `?query` passes the guard but opens a different file
